- **状态：** Proposed（2026-10-12 修订，未签署）。v5 提案：没有已接纳结果时不采用旧 invocation 的输出，也不放宽当前 attempt 守卫。尚未接受。

## 问题

模型返回的满分、复核标记和 confidence 不能变成控制面。别名模型会在不改名的情况下变掉。高置信度误判比低自动率更危险。

## 方案

### A. 推荐：一份版本化 JSON Schema + 冻结闭包语义校验 + 默认人工

- Schema 分为 `model-grade-payload/1.0.0` 与 `acceptance-envelope/1.0.0`。合并草案已撤回。
- 满分、题目、评分点和组合函数只来自冻结 rubric。`criterion_sum` 要求 id 集合完全一致，建议分等于点数之和。8.00 对 3.00 拒绝。
- 证据要有页以及顺序合法的 bbox 或 span，并落在该 generation 的 page set。不保存思维链。
- 模型元数据来自调用配置与供应商响应，不来自模型自报。
- 非法输出进入有限次纠正或人工异常，不补零。
- 谱系保存在 invocation 行。拿不到可锁定 revision 时明确记录，不承诺逐位重现。
- fallback 只允许已登记且该题型基准通过的配置，并重算复核等级。
- 批量资格由策略快照决定。未验证配置一律人工。confidence 不是概率。
- 校准集与测试集分开。样本不足时不设置自动放行阈值。

### B. 信任模型自带的 reviewRequired 与 maxScore

与 R15/R24 冲突。不推荐。

### C. 现在就写死准确率门槛

与 R22/R24 冲突。不推荐。

## 代价

默认人工会提高 M3 的教师工作量。这是在没有真实答卷基准之前的保守选择。质量报告必须把合成样本和真实样本分开，不能合成通过就宣称学校准确率。

## 兼容与回退

Schema 破坏性变更使用新的 `schema_version`。旧 job 只接受创建时登记的 schema。已发布成绩不因新 schema 改写。

## 故障模型

截断 JSON、额外字段、错误题号、越界、NaN、评分点合计矛盾、缺证据、提示注入、模型拒绝、别名漂移、未经基准的 fallback。

## 验收

上述样例不写正式分。正式分可以反查到 invocation 与冻结哈希。批量确认在无校准策略时不可用。测试未运行，也没有真实学生基准。
