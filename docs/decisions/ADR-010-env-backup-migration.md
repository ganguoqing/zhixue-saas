# ADR-010 环境分离、备份恢复与迁移兼容

- **状态：** Proposed（2026-10-12 修订，未签署）
- **2026-10-13 M0 范围：** 项目负责人在对话中批准决议清单第 2 节对本 ADR「建议批准」列的条款，并接受第 3 节保守恢复政策。见 `g0-decision-record-20261013.md`。同表「仍保留待定」列和未列入的未来细节仍是 Proposed。本 ADR 整体不是 Accepted。
- **日期：** 2026-10-11；修订 2026-10-12
- **2026-10-12：** M0 最小环境见修复稿 v2 第 4 节：三套资源名模板、单一迁移锁、mock 端点默认、日志字段、三个指标。生产 RPO/RTO 仍不填数字。
- **决策责任：** 项目负责人。Docker + 托管服务已由 R27 确认。RPO/RTO 未确认。
- **关联：** R26、R27；F25、F26
- **证据：** 不把 Kubernetes 提前做成首期平台。不预设恢复时间数字。

## 问题

只备份数据库会丢掉答卷对象。恢复 Redis 可能重放旧任务并改写新成绩。不可逆迁移不能靠 down migration 找回数据。

## 方案

### A. 推荐：三套环境完全分资源；PostgreSQL 为任务真相；迁移四阶段

- 开发、测试、生产各自的数据库、桶、Redis、密钥、模型配额和网络。
- 生产形态保持 Docker 应用 + 托管 PostgreSQL + 对象存储。
- 备份包含数据库时间点与对象版本。恢复到独立环境后核对指针、哈希和审计。
- 恢复出的队列若重放，消费者按 aggregate_version 与取消标记拒绝改写新分。
- 迁移：expand → 回填 → 校验 → contract。单一迁移锁。失败用前向修复，不假设向下迁移恢复已删行。
- API、Worker、事件 schema 保留兼容窗口。发布包含健康检查与优雅停机。
- RPO/RTO 留空，待业务批准后写入本 ADR 的修订，不在本文件编造。

### B. 首期单机包含数据库

与 R27 冲突。不推荐。

### C. 首期 Kubernetes

与“预留、不作为第一阶段”冲突。不推荐。

## 代价

三套环境增加费用。兼容窗口会推迟删除旧列。优雅停机若短于模型调用，任务要靠租约恢复，而不是靠请求一直活着。

## 兼容与回退

应用回滚到上一版本时，数据库必须仍处于该版本能读的 expand 阶段。contract 完成后再回滚应用会失败，这要在发布检查里挡住。

## 故障模型

生产误用测试密钥、只恢复数据库、队列重放、滚动发布中新旧 Worker 共存、迁移执行到一半进程退出。

## 验收

独立环境恢复一场含已发布、修订中、处理中的考试，指针与对象一致，旧任务不改新分。该演练未做。
