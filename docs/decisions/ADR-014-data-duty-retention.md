# ADR-014 数据职责、样本授权、保留与删除

- **状态：** Proposed（2026-10-12 修订，未签署）
- **2026-10-13 M0 范围：** 项目负责人在对话中批准决议清单第 2 节对本 ADR「建议批准」列的条款，并接受第 3 节保守恢复政策。见 `g0-decision-record-20261013.md`。同表「仍保留待定」列和未列入的未来细节仍是 Proposed。本 ADR 整体不是 Accepted。
- **日期：** 2026-10-11；修订 2026-10-12
- **2026-10-12：** M0 可单独决议的范围仍是合成数据加已授权试卷/答案、禁止真实学生数据、端点允许名单默认只有 `mock://local`。保留年限继续空白，不虚构。
- **决策责任：** 项目负责人。本 ADR 不是法律意见，也不认定某项许可已经完成。
- **关联：** R18、R22、R25、R27；F24
- **证据：** 已确认中国大陆优先、未成年人数据需要保护、真实学生答卷尚待协调、到期不删除。处理者角色、告知文本、保留年限和备案责任人未确认。

## 问题

试卷、答卷、成绩、日志、缓存、备份和模型临时文件是不同的数据流。只遮住姓名并不等于匿名。只删主库会把答卷留在对象存储和备份里。

## 方案

### A. 推荐：M0 最小政策 + 真实数据前的专项闸门

M0：

- 允许已书面授权的试卷和标准答案进入指定环境和指定端点。
- 不允许真实学生答卷、姓名、学号和成绩。
- 合成数据用于流程。
- 默认日志不记录答卷正文和个人标识。
- 模型请求使用匿名 job，不附学生姓名。
- 未列入允许名单的端点配置直接拒绝。

真实学生数据进入测试或生产之前，必须另有书面决议，至少写明：学校与平台的处理角色、依据、告知与监护人同意如何完成、供应商是否再处理、允许区域、保留期限、导出与删除、备份何时到期、谁负责备案/等保/生成式 AI 适用性判断。

删除用 TOMBSTONE 清除载荷，并在备份恢复后重放删除标记。审计完整性不能用来拒绝依法删除；能保留的是不含载荷的事件键，且这一点仍要在专项里确认。

### B. 把“境内部署”或“已脱敏”直接当成合规完成

不推荐。审查报告已指出这不足以下结论。

### C. 为了演示导入未授权学生卷

与 R18/R22 冲突。禁止。

## 代价

M0 的 AI PoC 不能代表真实学生评分质量。专项未完成时，M3 可以继续用合成数据做功能，不能做真实数据试点。

## 兼容与回退

允许名单上的端点可以增加，必须留记录。从名单删除后，新调用失败；已经合法保存的历史结果按保留政策处理，不自动扩散到新端点。

## 故障模型

未授权端点、日志泄露答卷、删除只影响主表、备份恢复把已删数据复活且没有重放、把合成指标写成学校准确率。

## 验收

样本台账能看出谁授权了哪份试卷、进了哪个环境。真实学生数据在专项完成前的配置检测为拒绝。全链路删除演练未做。
