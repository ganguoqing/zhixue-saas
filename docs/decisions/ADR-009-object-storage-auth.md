## 问题

对象键若可猜测，或签名 URL 被转发，撤权不会立即生效。ZIP 与 PDF 还能在解析阶段耗尽资源。上传未完成就评分会把半份文件当成答卷。

## 方案

### A. 推荐：私有桶 + 服务端 key + 短时上传签名 + 下载走鉴权代理

- key 由服务端生成，包含环境与租户，不采用用户提供的路径。
- 上传签名只覆盖该 key、方法、大小和短 TTL。建议起点 15 分钟，未实测，可配置。
- 下载不使用可转发的长寿命签名。代理再次检查成员、数据范围和租户状态。
- 对象版本与 sha256 写入 `stored_objects`。证据对象不覆盖。
- finalize 之前不创建评分任务。
- ZIP：拒绝路径穿越，限制成员数、解压比例和总字节。具体安全上限在 M0 配置，不当作学校容量承诺。
- 校验实际类型与页数。解析进程有资源限制。
- 未引用对象进入 quarantine 后删除。

### B. 下载也用短签名

实现简单，但 TTL 内转发仍然有效，撤权不即时。若产品以后接受这个窗口，必须写明窗口长度。

### C. 公开桶靠难猜 URL

不推荐。

## 代价

代理下载占用应用带宽。即时撤权因此才能做到。大文件要测超时，而不是假设代理适合所有扫描件。

## 兼容与回退

已签发的上传签名在 TTL 内仍然有效。撤权不能追溯销毁已经发出的上传签名，所以 TTL 必须短，且 finalize 时再检查授权。

## 故障模型

越权 finalize、越权下载、伪扩展名、ZIP 炸弹、分片超时、对象在而数据库回滚、数据库在而对象丢失。

## 验收

上述用例失败且不触发正式任务。旧对象版本仍可由已发布证据哈希读到。测试未运行。
