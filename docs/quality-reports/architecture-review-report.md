## 1. 执行摘要

初稿与产品的总体方向一致：学校 SaaS、数学首发、模块化业务后端、独立 AI 服务、教师确认正式成绩、版本追溯和异步处理。技术栈无需因本次审查整体推翻。

但文档尚不足以作为 Cursor 的确定性实现规格。最重要的缺口是：数据库无法据此建立完整的租户一致性约束；业务状态、队列与对象存储之间缺少故障恢复协议；多个批改状态机没有跨聚合不变量；教师复核与迟到 AI 结果的并发冲突未定义；成绩修订没有完整传播到掌握度、诊断、建议与教学效果评估。

发现共 **28 项：Blocker 3、Critical 13、Major 11、Minor 1**。这些是文档层面的设计缺口与条件性风险，不是已证实的生产漏洞。Blocker 为 F01（租户约束）、F08（事务与事件）、F15（授权与数据库隔离契约）。

**M0 判定为 Conditional Go：** 可开始仓库骨架、隔离的合成数据实验及 AI PoC。涉及正式基础模型、授权和任务提交的实现，必须先通过第 8 节 G0 设计门槛；M0 退出必须通过 G1。不能直接以当前初稿开展完整 M3 阅卷系统，更不能导入未获授权的学生数据或发布正式成绩。此范围限制是本次审查建议，不更改产品需求。

本报告独立保存，未修改原需求或架构初稿。修复建议、状态表及候选数据结构均待 ADR 决议，不自动成为已确认决策。

## 4. 严重度定义与发现清单

**Blocker：** 核心安全/一致性实施边界无法确定，必须在相关基础实现前决议。  
**Critical：** 可能导致越权、错误归属、正式成绩失真、不可恢复或敏感数据违规处理，必须在相关功能验收/使用前关闭。  
**Major：** 影响需求覆盖、可运维性、扩展性或成本控制，须按里程碑关闭。  
**Minor：** 文档与契约表达缺陷，不单独阻断验证。

### F01 — Blocker — 缺少可强制执行的租户归属与复合外键

**证据：** A§2.1–2.6 只给出实体名称和主要关系，未列业务表 tenant_id、唯一约束、外键及删除规则；B§3.1 要求明确租户归属。  
**风险：** 单列外键只证明父对象存在，不能证明同租户；A 校 answer 可能引用 B 校 attempt，后续查询过滤也无法修复污染。  
**修复：** 建立“全局身份/平台内容/租户内容”清单；租户表 tenant_id NOT NULL，父表 UNIQUE(tenant_id,id)，子表 FOREIGN KEY(tenant_id,parent_id)；考试、答案和评分还须约束同一试卷版本与题目槽位。全局内容通过显式授权或租户快照桥接，禁止用 nullable tenant_id 充当普遍绕过通道。历史事实采用 RESTRICT/归档，级联删除仅限明确的草稿生命周期。  
**验收：** 在实际应用数据库角色下，跨租户 INSERT/UPDATE 被拒；同租户但跨考试/跨卷版本引用被拒；删除被正式成绩引用的版本失败。提交完整 ERD、数据字典及迁移约束测试。  
**关闭门槛：** G0 决议，G1 基础示例验证，M1–M3 随新增表复验。

### F02 — Major — 时间有效性有概念，无完整约束与查询语义

**证据：** A§2.2 只说明“带生效时间”；R13/B§4 要求历史归属；A§2.6 未说明教学事件目标的时间口径。  
**风险：** 转班导致历史统计漂移；当前授权和历史任课关系混用；补录、同日转班、重叠入班无法确定。  
**修复：** 生效区间统一为半开区间 [valid_from,valid_to)，明确学年/学期与班级的关系，区分业务发生时间与系统记录时间。为考试冻结参考名单及当时班级；教学事件冻结目标学生。行政班同一学生同一时段禁止重叠，任课关系允许多教师但限制完全重复；历史归属不能自动授予现任或离任教师访问权。  
**验收：** 转班、升班、跨学期任课、补录及区间边界样例保持历史归属；时间范围无效或不允许的重叠被拒；授权按独立政策判断。  
**关闭门槛：** M1。

### F03 — Critical — “版本冻结”未闭合到题目、资产及评分依赖

**证据：** A§2.3–2.5 提出固定版本，却未说明 options/answers/knowledge_links/assets 引用哪个版本；冻结建议为“正式考试开始后”。  
**风险：** 开考前后的竞争窗口、修改附件或题目知识映射都会改变既有评分依据；重批时无法还原原卷。  
**修复：** 考试启用或接受首份答卷前完成受控冻结；绑定 paper/question/answer_key/rubric/graph/学校覆盖层版本及不可变资产摘要。max_score、评分点和题目顺序全部纳入冻结。发布版本不可原地 UPDATE；纠错创建新版本与受审批准的重评方案，不静默改分。  
**验收：** 发布后修改逻辑题目、图片、答案、规则及图谱，历史考试仍读取同一内容摘要；冻结与首个提交并发时不存在半冻结数据。  
**关闭门槛：** M2 内容版本，M3 考试冻结。

### F04 — Critical — 成绩审计缺少正式版本、批准与不可覆盖约束

**证据：** A§2.5 列 score_revisions，A§6.4 展示保留 AI/教师分数示例，未定义正式成绩模型、修订前后链及写权限。  
**风险：** 修改仍可能覆盖最终字段；总分和逐题分数不一致；改分无法证明谁在何授权下批准。  
**修复：** 将 AI proposal、人工 review、不可变 score_version、revision_request 和当前生效指针分离。保存前后版本、理由、操作者 membership、授权上下文、时间及关联命令；逐题和总分在同一业务事务校验。限制运行角色更改已发布事实，记录权限/教学事件修改审计；定义审计保留、完整性与受控更正策略，避免“审计永久留存”绕过删除义务。  
**验收：** 6→8→7 三次变化完整可追溯；直接覆盖已发布分数被拒；事务失败不留下半次修订；历史操作者离校仍能展示适当的审计身份。  
**关闭门槛：** M3，M0 验证审计事务机制。

### F05 — Major — 三级题库与学校图谱覆盖的授权模型未定义

**证据：** A§2.3/2.4 仅列覆盖关系与所有权范围；R08 需分离所有权、使用授权、共享权限。  
**风险：** 教师个人题库借“本校可读”泄漏；公共题目授权撤销导致历史考试不可解释；学校内容误共享。  
**修复：** 明确 owner、visibility、grant、发布审批、复制/引用策略及版本谱系；教师私有 owner 使用租户 membership；知识边两端必须属于兼容图谱版本。考试持有合法授权的冻结快照，撤销新使用授权与历史保留分开处理。学校导入默认私有。  
**验收：** 同租户另一教师也不能读取私有题；未审批内容不可公开；授权撤销后的新考试被拒且既有历史快照按保留政策仍可追溯。  
**关闭门槛：** M2。

### F06 — Major — 已确认输入路径与生成能力未完整落位

**证据：** R03/R06/R16 的 Excel 总分、逐题得分、学生导入，R05/R06 的 Word 标准答案/手动录入，R06 的已批改卷，R05/R08 的 AI 生成练习/题目审核；A§4/§6 主要描述新答卷 OCR→AI 评分。B 汇总未完整保留格式和导入要求。  
**风险：** Cursor 只做一种 AI 路径，学校既有阅卷流程不受支持；仅总分数据被臆造为逐知识点证据；教师已有分数误当 AI 评分。  
**修复：** 补齐来源类型、import_batch/import_row、字段映射、逐行校验、学生匹配、人工预览确认和重复导入策略。已批改卷提取教师得分，不默认重新评分。只有总分时不得生成缺乏逐题依据的知识诊断。将 Word 答案解析/手工规则、AI 生成题审核与练习下载/打印安排到明确里程碑；范围变化须记录，不推定删除。  
**验收：** 三路径（新答卷、已批改卷、Excel）都经身份/复核/确认进入统一正式成绩；Word/手工标准答案可版本化确认；仅总分标为有限证据；未审核生成题不能入正式题库。  
**关闭门槛：** G0 需求映射；M1 学生导入，M2 生成题，M3 成绩与答案接入，材料增强由路线明确。

### F07 — Major — 模块目录不能替代数据所有权和依赖规则

**证据：** A§3.1 Exam“学生作答”、Submission“识别任务”、Grading“评分”、AI Orchestration“编排”存在交叉；common 边界未定义。  
**风险：** 模块相互访问 repository、循环依赖、鉴权放在入口后内部调用绕过；一个巨型 orchestration Service 占有全部事务。  
**修复：** 给每张表指定唯一写入模块，给跨模块命令指定事务协调者。建议 Exam 管考试/名单、Submission 管原件/归属/答案来源、Grading 管建议/复核/正式分数、Orchestration 管任务/执行尝试、Subscription 管额度。只公开命令/查询接口；受控共享 Unit of Work 可承担本地原子事务，异步派生走事件。common 只容纳技术基础设施。  
**验收：** 提交有向依赖图、所有权矩阵、命令与事务表；架构检查拒绝跨模块 repository 引用和循环依赖；内部命令直接调用也执行授权与不变量。  
**关闭门槛：** G0 原则，M0 边界示例，此后每阶段检查。

### F08 — Blocker — Outbox 未成为完整的事务与投递协议

**证据：** A§3.2 仅建议 Outbox；A§4.2 仍是“创建 Job→写 BullMQ”的分步流程。  
**风险：** DB 成功队列失败丢任务；队列成功 DB 回滚产生幽灵任务；确认成绩后未通知下游。  
**修复：** 在同一 PostgreSQL 事务保存业务状态、processing_job、必要审计与 outbox；独立 relay 领取投递，ACK 后标记已投递，超时重投。消费端以 consumer+event_id 的 inbox/幂等记录和派生写入同事务去重；事件包含 tenant、aggregate、revision、schema_version。对象上传无法加入 DB 事务，需 finalize、待清理对象和对账协议。Outbox 也不能保证下游只收到一次。[AWS 官方说明](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)。  
**验收：** 在提交前、提交后/入队前、入队后/标记前逐点终止进程，结果不丢、无幽灵写入、重复事件不产生重复正式成绩；relay 可多实例并发；对象孤儿可回收。  
**关闭门槛：** G0 ADR，G1 故障注入。

### F09 — Critical — 确认/发布与成绩修订的派生数据一致性未定义

**证据：** A§3.2 在 ExamScoresConfirmed 后启动掌握度；A§6.3 把 Published 定义为进入分析；没有 ScoreRevised 的下游协议。  
**风险：** 已确认未发布数据提前进入分析；修订后掌握度、建议、教学评估仍引用旧分数；旧任务迟到覆盖新结果。  
**修复：** ADR 确定正式分析资格及唯一触发事件。派生结果绑定 score_version、evidence_set_version、graph_version、algorithm_version 和分析窗口；修订事件触发受影响范围的重算/失效标记。旧版本结果不能更新当前指针；建议去重保留历史，教学事件评价标记“待重评”。时间衰减计算使用固定 as_of，不依赖重跑当天时钟。  
**验收：** revision 2 先完成、revision 1 后完成，当前分析始终指向 2；修订重算可恢复且无重复证据；界面能识别旧分析和待更新状态。  
**关闭门槛：** M3 事件契约，M4–M6 实现闭环。

### F10 — Major — Python Worker 的执行拓扑与版本兼容性待决

**证据：** R19 已确认 BullMQ+Python Worker；A§1/§4 只写 Worker→FastAPI，未给运行时、包版本及协议。  
**风险：** Cursor 错误认为 Python 不能消费 BullMQ，擅自改栈；或未经跨语言验证便使用不兼容特性；FastAPI 再建另一套无持久化任务状态。  
**修复：** 首先验证已确认路线：NestJS producer→官方 Python BullMQ Worker→FastAPI 推理→NestJS 接收结果。固定 Node/Python BullMQ、Redis、协议版本并测兼容；CPU 处理移出事件循环以免锁续租受阻。只有实测不满足要求时才提交 Node Worker 调用 Python 服务的变更 ADR。FastAPI 不另行拥有业务任务生命周期。[BullMQ Python 官方文档](https://docs.bullmq.io/python/introduction)确认有 Worker API；其可用性不等于所选版本与特性已经验证。  
**验收：** Node 投递、Python 消费/重试/锁恢复/优雅退出/结果回传均有运行证据；FastAPI 重启后业务状态仍由 NestJS/持久任务记录恢复。  
**关闭门槛：** M0。

### F11 — Critical — 幂等键没有绑定输入版本与执行世代

**证据：** A§4.3 要求唯一 ID/幂等键，未定义作用域、持久约束、重评与重试的区别。  
**风险：** 重试重复改分/结算；仅按文件摘要去重误合并不同考试；同一 jobId 被清理后不再有业务防重；旧 Worker 回写覆盖新人工结果。  
**修复：** 逻辑任务键包含 tenant、stage、业务对象、input_revision/hash、评分配置版本和受控 generation；不同考试不可混并。execution_attempt 与逻辑任务分离；结果提交携带期望输入版本、租约 token/fencing epoch 和 artifact hash，NestJS 原子 CAS+唯一约束提交；人工修改提升输入或复核版本，使旧结果失效。  
**验收：** 重复消息/重复回写只生效一次；同文件用于两个考试保持独立；Worker A 租约过期、B 接管后 A 回写被拒；人工改分后旧 AI 结果不覆盖。  
**关闭门槛：** G1 原型，M3 全流程。

### F12 — Critical — 批量部分失败、重试预算及队列丢失恢复未建模

**证据：** A§4.3 说仅重试失败答卷，未给 batch/item/page/stage、终止态与恢复协议；A§6 FAILED_RETRYABLE 无返回路径。  
**风险：** 多页答卷缺页被误判成功，重试全部导致重复成本，Redis 清空后数据库显示处理中却永不恢复。  
**修复：** 建立批次→答卷项→阶段依赖，页完整性 manifest，成功/失败/待人工分别汇总；定义可重试（网络/429/暂时 5xx）、不可重试（非法文件/权限/配置）及需人工（身份/评分歧义）。按逻辑任务设置指数退避、抖动、最大尝试/截止时间、失败隔离队列；reconciler 基于持久 job、租约和阶段检查点补发丢失工作。BullMQ stalled 是恢复事件，不能充当全部业务终态。[BullMQ stalled 机制](https://docs.bullmq.io/guide/jobs/stalled)。  
**验收：** 300 项中 295 成功/5 失败只重跑 5；多页缺页阻止发布；杀 Worker、清空测试队列、恢复 Redis 后无永远悬挂任务；耗尽重试进入可见终态。  
**关闭门槛：** M0 恢复原型，M3 批量实现。

### F13 — Critical — 回传/回调没有服务身份与防重放契约

**证据：** A§4.1/4.2 的“将结果交给业务 API 验证”未描述认证、授权和信任边界。  
**风险：** 伪造结果、重放旧结果、跨租户任务替换、凭高权限 Worker 直接发布正式成绩。  
**修复：** 选择返回响应或异步回调，均使用受限服务身份；内网/mTLS或短期 audience/scope 凭据。签名回调须有时间窗、nonce/event_id、签名密钥轮换与防重放。tenant/exam/student 由服务端 job 查询得出，不能信任 payload。校验结果属于当前输入、当前租约和允许状态；Worker 无确认/发布权限。  
**验收：** 错误身份/签名、过期凭据、错误 tenant、重放、已取消任务、旧 generation 均拒绝且不写正式分数；合法重复 ACK 不重复写入。  
**关闭门槛：** G1 服务契约，M3 全面复验。

### F14 — Major — 用量统计未形成预留、实际结算与对账

**证据：** A§2.1 usage_records 只有 resource_type/quantity；A§4.3 只写成本统计；R25 明确配额与可追踪成本。  
**风险：** 并发任务超额，超时但供应商已计费无法归账，重试实际多次调用被业务去重错误地抹去成本。  
**修复：** 将额度预留、释放、实际消耗和供应商成本账分开；以租户/期间原子 reservation 防并发超额。每次真实 invocation 保存 request_id、attempt、页数/token、价格版本、币种及估算/确认/未知状态。逻辑任务效果幂等，不承诺外部调用只收费一次。超时未知消耗先对账再决定重试；套餐限制不替代数据权限。  
**验收：** 并发配额测试不超发；一次逻辑任务两次真实付费调用都有账；未知成本不记零，预留可清理；每考试汇总可追溯到调用明细。  
**关闭门槛：** M0 用量骨架，M3 AI 成本，M7 商业配额。

### F15 — Blocker — RBAC、数据范围和 RLS 的实施契约未闭合

**证据：** A§5 为层次原则和六个样例；roles.scope 不能表达学科/年级/班级授权；R12/B§2 限制平台管理员读取个人记录。  
**风险：** 只测试跨校却漏掉校内跨学科；连接池泄漏租户上下文；应用使用表 owner/superuser 绕过 RLS；权限撤销仍被缓存接受。  
**修复：** 建立 action×resource×tenant×subject/grade/class×有效授权矩阵，服务端可信 membership 与角色计算上下文。ADR 决定 RLS：若采用，对租户表 USING 与 WITH CHECK、无上下文 fail closed，事务内 SET LOCAL/等价受控机制；运行角色不为 owner/superuser且无 BYPASSRLS，迁移/运营角色分离。平台运营默认只读租户与用量，个人记录访问需限时明确授权并审计。RLS 提供租户行边界，班级/学科范围仍须另行保证。[PostgreSQL 官方文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)说明 owner及 BYPASSRLS 绕过与外键检查不受 RLS 过滤，故不能把 RLS 当成复合外键或全部授权的替代。  
**验收：** 真实运行角色验证 SELECT/INSERT/UPDATE/DELETE、原生 SQL、JOIN、导出、后台任务；同池 A→B→无上下文并发无串租户；校内跨班/学科、平台管理员、撤权、全局资源例外均覆盖。若不采用 RLS，须提交同等级隔离方案与漏过滤测试证据，不能仅标“后续评估”。  
**关闭门槛：** G0 ADR，G1 全链路越权测试。

### F16 — Critical — 文件隔离、上传安全与保留链不完整

**证据：** A§4.2 “文件写入对象存储→Submission”；A§5.1 只要求服务端授权；R16 支持 ZIP/PDF。  
**风险：** 对象引用跨租户、签名链接泄漏、ZIP 路径穿越/解压炸弹、PDF 解析耗尽资源、上传未完成却进入评分。  
**修复：** 文件元数据绑定 tenant、业务用途、不可变 object_version/hash；服务端生成 key，私有 bucket，受限上传会话与校验后的 finalize。校验实际类型、大小、页数、解压比例/成员数量与路径，限制解析进程资源；原件和派生资产同样授权。下载使用短时授权或鉴权代理，签名 URL 是可转交凭据，需确定 TTL及撤权边界。补齐 multipart 超时清理、隔离区、存储配额、孤儿对账及删除策略。  
**验收：** 越权上传/finalize/下载失败；恶意 ZIP、伪类型、超限 PDF 不进入模型；未完成/损坏文件不触发正式任务；对象版本更新不改变旧证据。  
**关闭门槛：** M0 存储原型，M3 完整导入。

### F17 — Major — 租户生命周期与后台任务资源隔离未定义

**证据：** B§3 Trial/Active/Expired/Suspended/Closed；A 无状态权限表；R26 要求学校任务不长期占用所有资源。  
**风险：** 到期即删除、已停用租户继续调用 AI、A 校洪峰阻塞 B 校；缓存或周期任务串租户。  
**修复：** 决定状态×操作矩阵，区分拒绝新任务、允许在途完成、立即取消、保留/导出历史等策略；分布式缓存 key、锁、去重键、临时文件及周期调度均含 tenant/env。后台每次 claim 与提交检查租户状态/能力。建立全局与每租户并发限制、公平调度、供应商速率限制和背压；不预设开源 BullMQ 自带所有分组公平能力。  
**验收：** 到期/暂停中途任务符合已决政策；同名 key 两租户互不影响；A 批量积压时 B 仍在已商定等待预算内获得处理；无重叠周期调度。  
**关闭门槛：** M0 隔离规范，M3 调度，M7 订阅策略。

### F18 — Critical — 学生匹配和重匹配缺少考试名单约束

### F19 — Critical — 状态图没有转换表、守卫与并发控制

**验收：** 允许边全部覆盖；所有未列边返回拒绝且无副作用；并发确认只提交一版；取消/重传/人工修正后旧任务不能推进新世代。  
**关闭门槛：** G0 守卫契约，M3 完整状态机。

### F20 — Critical — 发布门槛与修订再发布路径不闭合

**证据：** A§6.3 REVISING→RECONFIRMED 终止，未回到生效发布；A§6.2 所有题均 REVIEW_REQUIRED，未表达合格客观题批量确认；A§3.2 与 Published 含义不一致。

### F21 — Critical — AI JSON 示例不能构成评分数据契约

### F22 — Major — 追踪版本不足以复现处理链

### F23 — Major — 质量指标存在，但未形成校准与发布门槛

**证据：** A§7 正确指出 confidence 不等于概率，未给复核路由；R24 要求题型基准和高置信度误判控制。  
**风险：** 模型 self-confidence 被直接用于批量通过；模拟集表现被声称是学校真实准确率；模型升级无人审核。

**验收：** 合成/真实样本分开报告；所有低可靠性和冲突样例被升级；模型/prompt/OCR/路由变化有回归报告；批量确认资格由平台校准策略决定并仍由教师确认。  
**关闭门槛：** M0 可行性，M3 基准，M7 真实试点质量。

### F24 — Critical — 隐私数据链与合法处理责任未落实

**证据：** A§8 只有日志不记录敏感内容；R18/B§14 涉未成年人、大陆优先；没有数据流/处理责任/供应商/保留与删除设计。  
**风险：** 学生身份随答卷发往不合适模型端点；把去标识化当匿名化；学校与平台之间处理责任不明；删除只覆盖主库。  
**修复：** 建立身份、答卷、成绩、诊断、日志、缓存、备份、AI 临时文件的数据清单/流向/处理目的/保存期限。按具体学校与业务确定处理者/受托者责任、合法基础、告知和监护人同意流程、权利请求、供应商再处理限制与影响评估。姓名遮罩并非匿名化，仍可回连学生的数据继续按个人信息保护。大陆优先不是对所有场景作绝对境内法定义务判断；默认使用获准区域端点，出境须专项确认相应条件。保留必要审计与依法删除采用受控策略及备份到期清除/恢复后重放删除标记。  
**验收：** 未获准端点被拒；模型请求不含无必要身份；授权样本台账可查；从申请删除到主库、对象、派生数据、缓存、备份生命周期都有可验证记录；试点前明确备案/等保/生成式 AI 等适用性与责任人。  
**关闭门槛：** M0 样本与数据流最小政策，M3 真数据前，M7 完整专项验收。

法律依据：不满十四周岁个人信息属于敏感个人信息，监护人同意和专门规则是重要要求；具体合法基础及适用例外需按实际业务核定。[个人信息保护法第13、21、28–31、55条](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)。加密、备份、访问控制、安全认证与事件处理也需落实为技术与管理措施。[网络数据安全管理条例第9条](https://www.mee.gov.cn/zcwj/gwywj/202410/t20241003_1087417.shtml)。

### F25 — Major — 指标列表未覆盖端到端失败与告警行动

**证据：** A§8 只列 API/队列/AI/成本等类别，没有 trace、SLO、停滞检测、告警阈值和责任。  
**风险：** “模型成功”掩盖结果没落库；队列空但任务卡住；费用未知持续积累；租户越权尝试无人处理。  
**修复：** 贯通 upload→job→attempt→invocation→result→score_version→projection 的 correlation ID；监控 outbox age、任务最老等待、租约超期、部分失败、版本冲突、分析延迟、未知费用与预算。确定告警责任、处理 runbook 和实测后服务目标；日志脱敏，避免敏感字段及高基数学生标识进入监控标签。  
**验收：** 演练模型超时、结果被拒、relay 卡住、队列丢失和成本异常，均可定位并触发对应处理；报告展示端到端等待/处理时间，不能只展示模型耗时。  
**关闭门槛：** M0 可观测骨架，M3 任务指标，M7 SLO。

### F26 — Critical — 部署、备份恢复和迁移无法据文档执行

**证据：** A§8/9 只有 Docker/托管/Migration 可运行；R27 要求环境独立、备份与恢复验证。  
**风险：** 生产共享测试凭据，数据库恢复却缺答卷对象；队列恢复重放旧任务；滚动发布新旧服务 schema 不兼容；不可逆迁移破坏冻结证据。  
**修复：** 开发/测试/生产独立 DB/bucket/Redis/密钥/模型配额与网络访问。明确 PostgreSQL 备份/PITR 能力、对象版本与备份、Redis 持久化/不驱逐策略及 PostgreSQL任务补偿；RPO/RTO 待业务批准并演练。迁移采用 expand→回填→校验→contract，明确唯一迁移执行者与锁、兼容窗口、恢复/前向修复策略；不要假定 down migration 可恢复已删除数据。API/Worker/FastAPI/事件 schema 有滚动兼容计划，发布含优雅停机、健康检查与秘钥轮换。  
**验收：** 从备份在独立环境还原一次包含已发布/修订中/处理中数据的考试，原件/摘要/审计/指针一致，旧任务不能改新分；上一版客户端和 Worker 在兼容窗口内正常；失败迁移演练可恢复。  
**关闭门槛：** M0 环境/迁移原型，M3 恢复核心考试，M7 生产演练。

### F27 — Major — M0–M7 缺少依赖、退出门槛与范围安置

**证据：** A§9 把很多目标列为 M0，但未区分验证和完整实现；B§16 未落订阅/配额、生成题、导入和修订传播的阶段。  
**风险：** M0 变成“大而全”；M3 才发现基础安全/任务不可行；M7 一次补齐全部运维；样本不足却验收为真实批改。  
**修复：** 按第 8 节门槛执行，M0 验证窄切片，不提前做全套阅卷。每阶段含需求 ID、依赖、交付、异常/权限测试、数据政策、QA 与架构复验；把 AI 用量骨架前移，订阅策略、生成题、Excel、Word 和分析重算明确落位。真实样本不阻断功能开发，但阻断真实质量宣称与试点质量准入。  
**验收：** 路线表每个 P0 有负责人/阶段/验收产物；没有未经实测的吞吐/准确率承诺；独立 QA 证据与人工验收分开记录。  
**关闭门槛：** G0 路线，持续阶段执行。

### F28 — Minor — 契约术语、错误码与 ADR 状态不统一

**证据：** A§3.2 的 ExamScoresConfirmed 与 A§6.3 的分析生效含义冲突；A§10 将已确认栈与待决实施项同列建议。  
**风险：** 开发者在相同名词下实现不同语义；评审无法辨认 Proposed/Accepted/Superseded。  
**修复：** 统一 submission/attempt/job/execution/proposal/review/score_version/published 的词汇，命令与事件分开命名；定义 403/404 防枚举策略、409 版本冲突、422 语义无效等错误契约与版本政策；ADR记录状态、证据、选择、后果和决策者。  
**验收：** 词汇表、OpenAPI、JSON Schema、事件示例与状态表无矛盾；全部 ADR 状态明确。  
**关闭门槛：** M0 文档包。

## 5. 数据与事务修复的最低设计产物

以下为需要提交的规格，不是批准后的 DDL。

### 5.1 ERD 必须体现的实体链

| 领域 | 最低关系与不变量 |
|---|---|
| 身份/租户 | user 1:N membership；membership→tenant；assignment→membership/role/具体范围；teacher→同租户 membership；student 首期不要求 user |
| 学校/时间 | tenant→academic_year→semester；class 的学年/年级/学期口径确定；student→有效 enrollment；teacher→有效 subject/class assignment；考试名单快照不随当前关系变化 |
| 内容版本 | graph→graph_version→node/edge；学校 overlay 有版本；question→question_version→选项/答案/资产/知识映射；共享授权有独立实体 |
| 考试 | exam→固定 paper_version/answer_key_version/rubric_version；paper_question 是考试题目槽位，关联固定 question_version；exam_roster→student/历史班级；attempt→roster |
| 采集 | upload_session→source_asset→submission/item/pages；submission 匹配 attempt；OCR/导入原始值→answer_revision；来源与证据质量可区分 |
| 批改/正式成绩 | answer_revision→grading_proposal；review 指向具体 proposal/answer_revision；score_version 汇总逐题正式分；revision_request 指向旧版本；published/current 指针唯一 |
| 异步/成本 | job→execution_attempt→invocation/result_artifact；quota_reservation 与实际 usage_ledger 分离；outbox/inbox 带租户和聚合版本 |
| 派生/干预 | mastery/diagnosis/recommendation/evaluation 引用正式 score_version 和证据集合；teaching_event 目标与执行时点快照，修订触发失效或重算 |

仅有 `(tenant_id, id)` 外键还不足以保证“同考试同题”。例如 student_answer 应通过其 attempt/exam 与 paper_question 的一致性关系或受约束桥接绑定，不能同时持有互不一致的 exam_id 与 question_id。跨平台/学校资源引用须用专门授权与版本快照设计，不强行套用不存在的同租户外键。

### 5.2 事务边界

| 命令 | 同一 DB 事务内 | 事务外工作 |
|---|---|---|
| FinalizeUpload | 验证会话/对象摘要，提交 submission、job、审计、outbox | 对象校验/扫描；失败对象隔离/清理 |
| AcceptAIResult | 验证身份/世代/输入/状态，写 proposal、执行结果、审计/用量事件 | 模型已调用；真实费用未知时后续对账 |
| ReviewAnswer | 验证 data scope 与期望版本，写 review/人工修订、使过期派生失效 | 无长时间推理进入本事务 |
| PublishScoreVersion | 守卫全满足，写不可变成绩、当前指针、审计、outbox | 异步计算掌握度/诊断/建议 |
| RepublishRevision | 新版批准，原子替换当前指针、审计、ScoreVersionPublished/替代事件 | 受影响派生重算与建议/评价失效 |
| ReserveQuota | 校验租户策略，原子预留额度、关联 job | 模型执行及实际账对账 |
| ApplyProjection | inbox 去重与派生写入/版本检查 | 接收事件可至少一次 |

严禁在持有 DB 事务/行锁期间等待 OCR 或模型 HTTP 调用。NestJS 为业务写入入口不等于每次写入必须经过公共 HTTP；可以采用有同等授权、不变量和事务约束的内部命令接口，须明确部署和服务身份。

## 6. 完整状态机应提交的转换契约

A 的三个状态图可作为讨论起点，但不能直接照枚举编码。本节为候选修复规范；命名可通过 ADR调整，守卫不可遗漏。

### 6.1 跨状态机不变量

1. 只有已 finalize、通过文件校验、页清单完整的当前 submission_generation 可以处理。
2. 只有明确匹配到当前租户/考试名单的答卷，才能形成学生评分建议；身份 OCR可先做，身份仍不确定时不写学生成绩。
3. 只有教师确认的题目结构、答案、rubric 和版本快照可作为评分输入。
4. review 必须指向当前 answer/proposal/config 版本。任何相关输入变化都撤销对应复核资格。
5. proposal 无权修改正式成绩；每次结果接纳须验证当前租约/世代/状态。
6. 正式发布只能包含已批准的完整 score_version；当前有效版唯一，异步派生引用其明确版本。
7. 修订属于新版本工作流；重试属于同逻辑输入的执行恢复，两者不能混用。
8. 缺考、未上传、空白答案、缺页、处理失败是不同事实，不统一补零。
9. 取消或失效使旧执行不能推进业务状态；已经发生的供应商成本仍须记账。
10. 平台计算复核要求，模型的 reviewRequired 或 confidence 只能作输入信号。

### 6.2 转换矩阵

| 聚合/原状态 | 命令/事件与目标状态 | 执行者、守卫与副作用 |
|---|---|---|
| Upload CREATED | StartUpload→UPLOADING | 授权教师；租户状态/配额允许；生成受限会话 |
| UPLOADING | FinalizeUpload→UPLOADED | 服务端确认对象存在、完整摘要、范围与上传会话；重复 finalize 幂等 |
| UPLOADING | Expire/Cancel→EXPIRED/CANCELLED | 会话超时或授权取消；中止 multipart/回收预留 |
| UPLOADED | Validate→VALIDATING→VALIDATED | Worker；受限解析、类型/页数/解压规则；非法文件→REJECTED |
| VALIDATED | Match→MATCHED 或 MATCH_REVIEW_REQUIRED | 自动匹配限定 roster；歧义保留候选，不猜测 |
| MATCH_REVIEW_REQUIRED | ResolveMatch→MATCHED | 有权教师；记录选择/理由；冲突不能跳过 |
| MATCHED | Recognize→RECOGNIZING→PARSED | 当前输入世代；生成 OCR/答案 revision；不确定→OCR_REVIEW_REQUIRED |
| OCR_REVIEW_REQUIRED | CorrectRecognition→PARSED | 教师修正，保留原文；提升答案版本并使旧评分失效 |
| PARSED | ValidateCoverage→READY_FOR_GRADING | 题目槽位/页完整性/当前身份已确认；缺漏→人工处理 |
| Grading PENDING | Schedule→QUEUED | NestJS；评分配置已冻结并获批准；同事务 job/outbox |
| QUEUED | Claim→RUNNING | 合法 Worker，租约/世代及租户政策通过 |
| RUNNING | AcceptValidatedResult→PROPOSED | NestJS schema+语义+世代校验；保存 AI建议，不发布 |
| RUNNING | TransientFailure→RETRY_WAIT | 可重试且预算未耗尽；到时回 QUEUED，并保留阶段检查点 |
| RUNNING/RETRY_WAIT | Exhausted/InvalidConfig→FAILED_FINAL 或 EXCEPTION_REVIEW | 明确失败码；人工解决配置后创建新输入世代，不能无限重试 |
| PROPOSED | RouteReview→REVIEW_REQUIRED 或 BATCH_CONFIRM_ELIGIBLE | 平台质量策略决定；低置信/主观/异常走人工，未经校准不批量放行 |
| REVIEW_REQUIRED | StartReview→UNDER_REVIEW→REVIEW_COMPLETED | 教师按当前版本复核、纠正分数/依据；有异常则不能完成 |
| BATCH_CONFIRM_ELIGIBLE | ConfirmSelected→REVIEW_COMPLETED | 授权教师；指定 ID+version+策略快照，任何变化均冲突，不自动确认 |
| Score DRAFT | CheckReady→READY_FOR_CONFIRMATION | 完整性、不变量、未决异常、复核覆盖通过 |
| READY_FOR_CONFIRMATION | Confirm→CONFIRMED | 当前授权教师，期望版本相符，批准记录持久化 |
| CONFIRMED | Publish→PUBLISHED | 当前全部守卫仍成立，原子当前指针+审计+业务事件 |
| PUBLISHED v1 | RequestRevision→新草稿 v2 | 有权教师给出理由；v1 继续有效；请求可批准/拒绝/撤回 |
| v2 REVISING | Review/Confirm→RECONFIRMED | 指向 v2 输入/评分规则；不能沿用不相符的 v1 复核 |
| v2 RECONFIRMED | Republish→PUBLISHED v2 | CAS 确保前驱仍 v1；v1→SUPERSEDED；原子替换及重算事件 |
| 未终结处理 | Cancel→CANCELLED | 政策允许的 actor；提交时检查取消，迟到结果拒绝 |
| 身份/答案/规则已变化 | Invalidate→SUPERSEDED | 保留旧证据；受影响复核/评分任务失效；新世代从相应阶段开始 |

CONFIRMED 是否立即成为分析资格、确认发布是否一个按钮，需 ADR 明确。推荐采用“一次产品操作，原子形成正式版本和发布事件”，或者确实保留双阶段但只在约定阶段触发分析；不能由不同模块自行解释。

部分发布/成绩撤回涉及产品语义，当前未确认，必须由 ADR 明确允许条件；不应为解决队列部分失败而默认允许不完整正式成绩。

### 6.3 非法转换验收

不得接受“传入任意 status 即更新”。必须拒绝：未匹配→评分、未审标准答案→评分、RUNNING→PUBLISHED、旧 proposal→当前复核、低可靠性题批量直达正式分、确认后篡改版本、被取消任务回写、已发布成绩原地覆盖、v2 发布后 v1 异步结果覆盖、无授权教师确认/重匹配。拒绝时成绩、审计业务事实与 Outbox 不得留下错误成功记录；可另写安全拒绝日志。

### 8.2 三道门槛

**G0：涉及基础模型/安全/事件的实现前。**

**G1：M0退出/进入M1。**

- 两租户+校内数据范围+平台运营角色的真实运行角色测试通过，无 Blocker 或 M0范围内 Critical。

- AI PoC包含真实试卷/答案（经授权）及合成答卷，公式/题目/答案匹配、时间/成本/失败样例报告完整；仅证明可行性，不证明真实学生质量。
- 独立 QA复验、架构复验与项目负责人验收分别记录。

**G2：学校生产试点前。**

- 所有 Blocker/Critical 关闭；Major须已关闭或由责任人书面接受有边界的残余风险，安全/成绩不变量不能豁免。
- 真实脱敏且获授权的答卷基准达到经学校确认的题型门槛；无充分样本时不能宣称已达真实评分质量。
- 正式成绩修订→掌握度→诊断→建议→教学事件效果的全链路复验通过。
- 数据职责/供应商/适用合规、容量/成本目标、备份恢复与生产迁移演练完成。
- 已决 RPO/RTO、队列公平和SLO有实测，不凭容量人数直接承诺处理分钟数。
